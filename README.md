# Lama Burst

Десктопный лаунчер для локальных моделей Ollama. Модель работает в ваших папках как агент: пишет код, ставит зависимости, запускает и проверяет результат, исправляет ошибки. Всё это под вашим контролем.

![Lama Burst](resources/icon.png)

Electron + React + TypeScript, около 7 600 строк кода, 108 юнит-тестов и живые сценарии на реальных моделях.

## Где здесь ИИ-инженерия

| Задача | Как решено |
| --- | --- |
| Модели 7–12B бросают задачу на полпути, сдаются после ошибки, не запускают свой код | Агентный цикл замечает эти паттерны и возвращает модель к работе отдельным сообщением; зацикленные ответы обрываются |
| У многих локальных моделей нет нативного tool calling | Два протокола инструментов: нативный через API Ollama и текстовый на тегах в системном промпте. История хранится в одном формате и собирается под нужный режим на каждый запрос — модель меняется посреди разговора |
| GGUF-импорты со «сломанным» шаблоном пишут вызов инструмента текстом | Отдельный разборщик распознаёт такие вызовы (`call:edit_file{...}`, JSON) |
| Модель портит файлы правками | После каждой записи — проверка синтаксиса (`node --check`, `ast.parse`, JSON); не нашлась замена — модель сразу получает настоящее содержимое файла |
| Длинная задача не влезает в контекст | Сначала сокращаются старые шаги, формулировка задачи остаётся |
| Агент с доступом к диску и PowerShell опасен | Песочница путей (блок `..`, абсолютных путей, junction и симлинков), права по категориям «авто / спрашивать / выключено», дифф перед записью, обязательное подтверждение удаления и опасных команд |

## Возможности

- **Автономная работа.** Скажите «создай сервис такой-то», и модель составит план, создаст файлы, установит пакеты, запустит, проверит запросом и исправит найденные ошибки. Если модель остановилась на полпути, сдалась после ошибки или не запускала свой код, Lama Burst возвращает её к работе.
- **Фоновые процессы.** Серверы и watcher'ы запускаются в фоне (start_process), их вывод можно читать между шагами, а запущенные процессы видны в верхней панели и останавливаются одной кнопкой. Долгие установки (tensorflow, torch) по таймауту не убиваются, а уходят в фон, и модель ждёт их окончания.
- **Живой вывод команд** прямо в карточке, пока команда выполняется.
- **Любая модель из Ollama.** Модели с нативным tool calling (qwen2.5, llama3.1 и т.п.) получают инструменты через API Ollama. Остальным (например, Tiger-Gemma, dolphin-mistral) инструменты описываются в системном промпте простыми тегами вроде `<read_file>docs/plan.md</read_file>`, а приложение само разбирает ответ.
- **Починка «сломанных» шаблонов.** Если GGUF-импорт выдаёт вызов инструмента текстом (`call:edit_file{...}` или JSON), вызов всё равно распознаётся.
- **Инструменты:** список файлов, чтение (в том числе по диапазону строк), поиск по именам и содержимому, создание и точечная правка файлов, переименование и перемещение, удаление в корзину Windows, команды PowerShell (установка пакетов, скрипты, git; таймаут по умолчанию 5 минут).
- **Права:** для каждой категории (чтение / изменения / команды) можно выбрать «автоматически», «спрашивать» или «выключено». Перед записью показывается дифф. Удаление файлов и опасные команды (удаление, `git push`, перезагрузка и т.п.) всегда требуют подтверждения.
- **PowerShell, а не bash.** Модель получает памятку по командам PowerShell. Если она всё же пишет `touch`, `grep` или `ls -la`, к ошибке добавляется подсказка, как переписать команду.
- **Песочница для файлов:** пути ограничены открытыми папками, обход через `..`, абсолютные пути, junction и симлинки блокируется.
- **Понимает готовые проекты.** Откройте папку с проектом, и Lama Burst сам, без модели, составит паспорт: стек, как запустить, как проверить, ключевые файлы, состояние git, предупреждения (не установлены зависимости, нет .venv). Заметки из `LAMA.md`, `AGENTS.md` или `CLAUDE.md` модель получает в каждом чате, а кнопка «Изучить проект» просит её саму написать `LAMA.md`. Файлы, упомянутые в сообщении, прикладываются к нему автоматически.
- **Ловит свои ошибки при правках.** После каждой записи файла проверяется синтаксис (`node --check`, `ast.parse`, JSON). Если замена не нашлась, модель сразу получает настоящее содержимое файла. Закончить, пока правка не применена, модели не дадут.
- **Длинные задачи не теряют цель:** если история не помещается в контекст, сначала сокращаются старые шаги, а сама задача остаётся. Зацикленные ответы обрываются.
- Несколько папок на чат, перетаскивание папок в окно, история чатов, индикатор заполнения контекста, свои инструкции, настройки модели (режим инструментов, `num_ctx`, температура).

## Установка

Нужны [Ollama](https://ollama.com) и Node.js 22+.

```powershell
npm install
npm run dist          # установщик: release\<версия>\Lama Burst Setup <версия>.exe
```

Разработка:

```powershell
npm run dev           # приложение с hot reload
npm test              # юнит-тесты
npm run typecheck
```

Проверка агента на реальных моделях (Ollama должна быть запущена):

```powershell
$env:LIVE_MODELS = "qwen2.5:7b,hf.co/TheDrummer/Tiger-Gemma-9B-v2-GGUF:latest"
npx vitest run src/main/agent.live.test.ts
```

Суффикс `#text` в имени модели (`qwen2.5:7b#text`) принудительно включает режим инструментов через промпт.

## Обновления

Сборки складываются в `release\<версия>\`. Установленный Lama Burst раз в минуту проверяет эту папку и, если там есть версия новее с правильной контрольной суммой, ставит её сам при закрытии приложения или сразу по кнопке «Обновить сейчас». Новая версия собирается командой:

```powershell
npm run release        # поднимает patch-версию и собирает установщик
```

Обновления берутся из локальной папки, а не из GitHub Releases: так удобнее для личных сборок. Путь к ней можно поменять в настройках. Копия, запущенная из `win-unpacked` без установки, обновляться сама не может и предложит установить себя.

## Как это устроено

```
src/main/agent.ts        агентный цикл: запрос → вызов инструмента → подтверждение → результат → снова модель
src/main/tools.ts        инструменты и ограничение путей
src/main/processes.ts    фоновые процессы
src/main/shell.ts        запуск PowerShell
src/main/project.ts      паспорт проекта и заметки (LAMA.md / AGENTS.md / CLAUDE.md)
src/main/attachments.ts  файлы, упомянутые в сообщении
src/main/updater.ts      обновления из папки release
src/main/prompt.ts       системный промпт и сборка истории под нужный режим
src/main/looseCalls.ts   распознавание вызовов, которые модель написала текстом
src/shared/textProtocol  теги для моделей без нативных инструментов
src/renderer/            интерфейс на React
```

История чата хранится в одном формате и для каждого запроса собирается заново. Поэтому модель можно сменить посреди разговора, в том числе с нативной на «промптовую».

Данные лежат в `%APPDATA%\Lama Burst` (настройки и чаты). Переменная `LAMA_BURST_DATA` задаёт другую папку, например для портативного режима.

## Проверено на моделях

Живые сценарии из `src/main/agent.live.test.ts`: модуль с тестами, HTTP-сервис с проверкой запросом, express с `npm install`, правка готового проекта, «Изучить проект».

| Модель | Режим | Новый код и сервисы | Правка готового проекта | Изучить проект |
|---|---|---|---|---|
| qwen2.5:7b | нативно | ✅ | нестабильно: иногда «улучшает» больше, чем просили | ✅ |
| Tiger-Gemma 9B v2 | через промпт | ✅ в большинстве прогонов (3–4 из 4) | ✅ | ✅ |
| gemma-4 12B coder (abliterated, Q4_K_M) | нативно / промпт | не проверялась | не проверялась | нестабильно |

Модели на 7–12B параметров заметно слабее облачных: путают порядок шагов, предлагают пользователю сделать что-то самому, повторяют одну и ту же ошибку. Lama Burst ловит эти случаи и возвращает модель к работе (в чате это видно отдельными строками «Lama Burst попросил…»). Для работы с кодом держите температуру низкой (0.1–0.4).
